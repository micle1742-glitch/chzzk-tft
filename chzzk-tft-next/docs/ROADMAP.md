# TIERON — ROADMAP
 
> 전체 구상과 개발 순서. 기능 기획이나 우선순위 판단이 필요할 때 읽는다.
> 개발 규칙·디자인·보안 원칙은 CLAUDE.md를 따른다.
 
## 한 문장 요약
 
실제 게임 계정의 티어를 인증하고, 그 인증을 개인 프로필·스트리머·랭킹·커뮤니티로 연결하는 게임 계정 인증 플랫폼.
단순 전적 검색 사이트가 아니다. TFT로 시작해 다른 게임과 스트리머로 확장한다.
 
## 목표
 
- **제품**: 게임 계정의 실제 티어를 인증하고, 다른 사람이 확인할 수 있게 한다.
- **확장**: 치지직 ↔ Riot 계정 연결, 프로필·랭킹·커뮤니티 구축.
- **학습**: Next.js → API → 인증 → DB/SQL → 보안까지 실제 서비스 개발 과정을 경험한다.
- 공부용으로 끝내지 않고, 실제 사용자에게 공개할 서비스로 발전시킨다.
## 최종 흐름
 
치지직 로그인 → 서버가 OAuth/세션 검증 → Riot 계정 연결 + 소유권 확인 → 서버가 Riot API 호출 → 사용자·인증 기록 저장 → 프로필 / 랭킹 / 커뮤니티 / 공유
 
> **티어 조회 ≠ 계정 소유권 증명.** 현재 카드만으로 소유권이 검증됐다고 간주하지 않는다.
 
## 기능 현황
 
| 기능 | 상태 | 내용 |
|---|---|---|
| TFT 티어 인증 | ✅ 구현 완료 | 게임 이름+태그 → Riot API → 티어/랭크/LP/승패/승률 카드, 로딩·오류·입력 검증 |
| 로그인·계정 연결 | 🔧 개발 예정 | 치지직 로그인, 치지직↔Riot 연결, 연결 해제/변경. 로그인 UI는 있으나 OAuth·소유권 검증 미완성 |
| 개인 프로필 | 🔧 개발 예정 | 사용자별 페이지, 연결 계정, 현재 티어·인증 상태, 배지, 링크 공유 |
| 랭킹 | 🔧 개발 예정 | TIERON 등록·인증 사용자 대상, 티어+LP 정렬. 정렬 기준·범위 미확정 |
| 커뮤니티 | 🔧 개발 예정 | 게시글·댓글, 이름 옆 인증 티어 배지, 신고·운영. 게시판 구성 미확정 |
| 게임 선택·확장 | 💡 아이디어 | 홈의 게임 메뉴 → 게임 선택 페이지. 다음 게임 미정 (API·인증 가능 여부 먼저 확인) |
| 티어 기록·배지 | 💡 아이디어 | 인증 이력, 티어 변동, 외부/방송 공유. TIERON이 직접 저장해야 가능 |
 
미확정 후보: 전적 상세, 게임별 랭킹, 스트리머 프로필, 티어 변화 그래프, 배지 공유, 관리자 기능, 알림, 광고·협업.
 
## 개발 순서
 
1. **Phase 1 — 핵심 기능** ✅ Next.js 이전, TIERON 브랜딩, Riot API 조회, 인증 카드, 로딩/오류 처리, 커밋·푸시
2. **Phase 2 — UI 마무리** ← 다음 작업. 홈·로그인·티어 디자인 통일, 모바일 대응, 로고·자체 엠블럼, 남은 GG TIER 명칭 정리
3. **Phase 3 — 로그인 인증** 치지직 OAuth, 서버 세션, 안전한 로그인 유지, 로그아웃·오류 처리
4. **Phase 4 — Riot 연결 + DB** 소유권 확인 방식, Supabase/PostgreSQL 결정, 스키마 설계, 인증 이력 저장
5. **Phase 5 — 프로필·랭킹** 사용자 프로필, 인증 배지, 등록 사용자 랭킹, 공유 페이지
6. **Phase 6 — 커뮤니티** 게시글, 댓글, 배지, 신고·운영
7. **Phase 7 — 확장·배포** 다른 게임, 티어 기록 시각화, 보안 점검, 배포·운영, 수익화 검토
> 확정 일정이 아니라 논의 기반 로드맵. 앞 단계가 완성되어야 다음 단계가 의미 있게 작동한다.
 
## 데이터 저장 위치
 
| 데이터 | 저장 방식 |
|---|---|
| 마지막 검색 닉네임, 화면 설정 | localStorage |
| 조회 결과의 일시적 상태 | React useState |
| 사용자 정보, 연결된 Riot 계정, 인증 이력 | DB |
| 로그인 세션 | 서버 세션 또는 안전한 쿠키 |
 
## DB 후보 테이블 (미확정)
 
- `users` — TIERON 사용자 ID, 치지직 계정 식별 정보, 가입일, 프로필
- `riot_accounts` — PUUID, 게임 이름, 태그, 지역, 사용자 연결
- `tier_verifications` — 대상 계정, 티어, 랭크, LP, 인증 시각
설계 시 중복 데이터, 외래 키, 유일성 제약 조건을 검토한다.
 
## 학습하고 싶은 주제
 
SQL 기초(SELECT/INSERT/UPDATE/DELETE), JOIN, 정규화·PK·FK, SQL Injection·매개변수화 쿼리, XSS, IDOR, 입력값 검증, OAuth·state 검증, 쿠키·세션(HttpOnly/Secure/SameSite), 서버 권한 확인, 환경변수 관리, API 호출 제한·오류 처리
 
## 수익화 (아이디어 단계, 결정된 것 없음)
 
광고로 운영비 충당, 스트리머 인증 프로필 활용, 커뮤니티로 이용자 확보, 성장 후 협업·후원.
검토 전 확인할 것: 이용자 수, 운영비, Riot API 이용 조건, 개인정보 처리, 게임사 정책.
