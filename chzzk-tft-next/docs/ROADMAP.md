# TIERON — ROADMAP

> 전체 구상과 개발 순서. 기능 기획이나 우선순위 판단이 필요할 때 읽는다.
> 개발 규칙·디자인·보안 원칙은 CLAUDE.md를 따른다.
> 2026-10 기획 확정 사항(권한, 페이지 구성, 인증 방식, 랭킹 규칙 등 상세)은 **docs/HANDOFF.md**에 있다. 이 문서와 충돌하면 HANDOFF.md가 우선한다.

## 한 문장 요약

실제 게임 계정의 티어를 인증하고, 그 인증을 개인 프로필·스트리머·랭킹·커뮤니티로 연결하는 게임 계정 인증 플랫폼.
단순 전적 검색 사이트가 아니다. TFT로 시작해 다른 게임과 스트리머로 확장한다.

## 목표

- **제품**: 게임 계정의 실제 티어를 인증하고, 다른 사람이 확인할 수 있게 한다.
- **확장**: 치지직 ↔ Riot 계정 연결, 프로필·랭킹·커뮤니티 구축.
- **학습**: Next.js → API → 인증 → DB/SQL → 보안까지 실제 서비스 개발 과정을 경험한다.
- **단기 목표**: 한 달 안에 포트폴리오로 보여줄 수 있는 범위(랜딩 → 로그인 → 인증 → 인증 카드 → 홈 → 조회 → 커뮤니티 최소 기능)를 완성한다.
- 공부용으로 끝내지 않고, 실제 사용자에게 공개할 서비스로 발전시킨다.

## 최종 흐름

```
[첫 사용자]  랜딩 → 치지직 로그인 → Riot 연결·소유권 확인 → 인증 완료(카드) → 홈
[인증 안 한 사람]  랜딩의 "홈으로" → 홈 → 인증 구역·다른 기능으로 이동
홈(허브) ┬→ 티어 조회 / 인증 / 내 프로필 공유 / 랭킹·커뮤니티 / 가이드
```

치지직 로그인 → 서버가 OAuth/세션 검증 → 치지직 ID로 사용자 자동 가입 → Riot 계정 연결 + 소유권 확인 → 서버가 Riot API 호출 → 사용자·인증 기록 저장 → 홈 / 프로필 / 랭킹 / 커뮤니티 / 공유

> **티어 조회 ≠ 계정 소유권 증명.** 조회 카드만으로 소유권이 검증됐다고 간주하지 않는다. 인증 배지는 소유권 확인이 끝난 계정에만 부여한다.

## 사용자 단계 (상세는 HANDOFF.md 6번)

| 단계 | 가능한 것 |
|---|---|
| 방문자 (로그인 안 함) | 랜딩·홈 구경, 티어 조회, 랭킹·커뮤니티 읽기 |
| 로그인 사용자 (치지직) | + 글쓰기·댓글, 인증 시작, 카드 저장 |
| 인증 사용자 (Riot 소유권 확인 완료) | + 인증 배지, 랭킹 등록, 글쓴이 옆 인증 티어 표시, 공개 프로필 |

## 기능 현황

| 기능 | 상태 | 내용 |
|---|---|---|
| TFT 티어 조회 | ✅ 구현 완료 (문구 수정 필요) | 게임 이름+태그 → Riot API → 티어/랭크/LP/승패/승률 카드. 조회 상태 카드에서 "VERIFIED" 표현을 "RIOT API 조회 결과" + 기준 시각으로 변경해야 함 |
| 랜딩 리디자인 | 🔧 다음 작업 | 스크롤형 랜딩, 다크·화이트 섹션 전환, 시그니처 선(한 곳), 나타나는 효과 |
| 치지직 로그인·자동 가입 | 🔧 개발 예정 | 치지직 OAuth, 서버 세션, 치지직 ID 기준 `users` 자동 가입. 로그인 UI는 있으나 OAuth 미완성 |
| 홈 허브 | 🔧 개발 예정 | 내 상태, 기능 입구 카드, 연결 계정 관리·설정. 미구현 기능은 "준비 중" |
| Riot 계정 연결·소유권 인증 | 🔧 개발 예정 (방식 미확정) | 한 페이지 안의 단계 카드. RSO는 승인 필요, 임시 후보는 프로필 아이콘 방식. 소유권 확인 단계는 교체 가능하게 분리 |
| 인증 완료 화면·공개 프로필 | 🔧 개발 예정 | 인증 카드(조회 상태 / 인증 상태 두 모습), 큰 "홈으로" 버튼, 공유용 페이지·OG 이미지 |
| 커뮤니티 | 🔧 개발 예정 | 게시글·댓글(글쓰기는 치지직 로그인만), 인증자는 이름 옆 인증 티어 표시. 신고·운영은 후순위 |
| 랭킹 | 💡 준비 중 | 커뮤니티와 한 화면(탭, 내비 "랭킹·커뮤니티"). 인증+공개 사용자, 티어→디비전→LP 정렬. 인증 방식 확정 전에는 가짜 데이터 없이 "준비 중" |
| 카드 꾸미기 | 💡 준비 중 | 데이터는 고정, 배경·테마 설정만 별도 저장 |
| 게임 선택·확장 | 💡 아이디어 | 지금은 TFT뿐이라 메뉴에서 빼거나 준비 중. 다음 게임 미정 (API·인증 가능 여부 먼저 확인) |
| 티어 기록·배지 | 💡 아이디어 | 인증 이력, 티어 변동, 외부/방송 공유. TIERON이 직접 저장해야 가능 |

범위 밖(후순위) 후보: 전적 상세, 티어 변화 그래프, 게임별 랭킹, 스트리머 프로필, 배지 공유, 관리자 기능, 알림, 광고·협업.
카드는 Riot API가 확실히 주는 값(지역, 닉네임#태그, 티어/랭크, LP, 승/패, 승률, 기준 시각)만 표시한다.

## 개발 순서

1. **Phase 1 — 핵심 기능** ✅ Next.js 이전, TIERON 브랜딩, Riot API 조회, 인증 카드, 로딩/오류 처리, 커밋·푸시
2. **Phase 2 — UI·랜딩 리디자인** ← 다음 작업. 현재 코드·CSS 파악 → 랜딩 구조 → 시그니처 선·나타나는 효과 → 모바일 대응, 남은 GG TIER 명칭 정리, 로고·자체 엠블럼
3. **Phase 3 — 로그인 인증** 치지직 OAuth, 서버 세션(HttpOnly 쿠키), 치지직 ID 기준 자동 가입, 로그아웃·오류 처리
4. **Phase 4 — DB + 홈 허브** Supabase/PostgreSQL 스키마, 권한 구분(방문자/로그인/인증), 홈 허브와 입구 카드
5. **Phase 5 — Riot 연결 + 인증 카드** 한 페이지 단계형 인증 화면(소유권 확인은 임시 방식, 개발용 가짜 확인은 개발 환경에서만), 인증 완료 화면, 카드 두 상태, 티어 조회 문구·기준 시각·쿨다운, 공개 프로필
6. **Phase 6 — 커뮤니티·랭킹** 게시판 최소 기능(목록, 글쓰기), 랭킹은 인증 방식 확정 후 활성화(그 전엔 준비 중)
7. **Phase 7 — 확장·배포** 다른 게임, 티어 기록 시각화, 보안 점검(가짜 확인 경로 차단 포함), 배포·운영, README·ERD·아키텍처 다이어그램, 수익화 검토

> 확정 일정이 아니라 논의 기반 로드맵. 앞 단계가 완성되어야 다음 단계가 의미 있게 작동한다.
> Riot 소유권 인증 방식(RSO 승인, 아이콘 방식 허용 여부)이 정해지는 시점은 불확실하므로, Phase 5의 인증 화면은 "되는 대로" 먼저 만들고 방식은 나중에 교체한다.

## 데이터 저장 위치

| 데이터 | 저장 방식 |
|---|---|
| 마지막 검색 닉네임, 화면 설정, 첫 방문 인트로 기록 | localStorage |
| 조회 결과의 일시적 상태 | React useState |
| 사용자 정보, 연결된 Riot 계정, 인증 이력, 인증 진행 상태 | DB |
| 로그인 세션 | 서버 세션 + HttpOnly·Secure·SameSite 쿠키 (localStorage로 로그인 유지 금지) |

## DB 후보 테이블 (미확정, 상세는 HANDOFF.md 7번)

- `users` — TIERON 자체 `id`(기본키), `chzzk_id`(중복 불가), 표시 이름, 가입일, 공개 설정. 저장하는 개인정보는 최소화
- `riot_accounts` — PUUID, 게임 이름, 태그, 지역, `user_id`, 인증 상태, `verification_method`
- `tier_verifications` — 대상 계정, 티어, 랭크, LP, 승, 패, 기준 시각 (승률은 저장하지 않고 계산)

설계 시 중복 데이터, 외래 키, 유일성 제약 조건을 검토한다.

## 학습하고 싶은 주제

SQL 기초(SELECT/INSERT/UPDATE/DELETE), JOIN, 정규화·PK·FK, SQL Injection·매개변수화 쿼리, XSS, IDOR, 입력값 검증, OAuth·state 검증, 쿠키·세션(HttpOnly/Secure/SameSite), 서버 권한 확인, 환경변수 관리, API 호출 제한·오류 처리

## 수익화 (아이디어 단계, 결정된 것 없음)

광고로 운영비 충당, 스트리머 인증 프로필 활용, 커뮤니티로 이용자 확보, 성장 후 협업·후원.
검토 전 확인할 것: 이용자 수, 운영비, Riot API 이용 조건, 개인정보 처리, 게임사 정책.
