# TIERON — HANDOFF (2026-10 기획 확정 사항)

> 이 문서는 지난 기획 대화에서 확정한 결정과 앞으로의 구축 방식을 Claude Code에 전달한다.
> 작업 시작 시 한 번 읽는다. CLAUDE.md의 디자인 규칙과 충돌하면 **이 문서가 우선**한다.
> 코드를 아직 보지 않은 상태에서 정리한 기획이므로, 실제 코드와 다르면 코드를 기준으로 알려 달라.

## 1. 목표

- 한 달 안에 포트폴리오로 보여줄 수 있는 TFT 티어 인증 서비스를 완성한다.
- 범위: 랜딩 → 치지직 로그인 → Riot 계정 연결·소유권 인증 → 인증 카드 → 홈 허브 → 티어 조회 → 랭킹·커뮤니티.
- 커뮤니티보다 DB·계정 연동이 먼저다.

## 2. 작업 원칙

- 기존 구조와 기능은 기본적으로 유지한다. 더 나은 구조가 있으면 바꿀 수 있지만, **무엇을 왜 바꾸는지 먼저 한두 줄로 설명**한다.
- 로그인, 티어 조회 API, 기존 라우트처럼 **동작 중인 기능을 바꿀 때는 수정 전에 확인**을 받는다. 레이아웃·스타일·문구는 확인 없이 개선해도 된다.
- 한 번에 한 화면씩 작업한다. 순서: 현재 코드 파악 → 계획 설명 → 수정 → 타입 검사·브라우저 확인 → 커밋 제안.
- 실제 CSS 변수와 색상을 먼저 확인하고, 확인 없이 새 색상 체계나 디자인 시스템을 만들지 않는다.

## 3. 디자인 방향

- 어두운 딥그린·블랙 배경 + 민트 포인트. 참고값: 배경 `#071A17` / `#050706`, 포인트 `#35E0B5`, 보조 `#0D3029`, 텍스트 `#F2F0E6`, 보조 텍스트 `#8BAAA0`. **실제 CSS 값이 우선**이다.
- Apple 웹사이트의 여백·타이포·절제와 치지직 개발자 페이지의 검정 + 흰색 + 민트 분위기를 참고한다. 흰색 중심 디자인을 복제하지 않는다.
- 랜딩은 스크롤형: 다크 섹션과 화이트 섹션을 번갈아 쓴다. 민트는 선, 점, 버튼, 아이콘 등에 제한적으로 쓴다.
- 흰 배경에서는 민트 글씨를 쓰지 않는다(대비 약 1.7:1). 텍스트 강조는 진한 초록(예: `#0D3029`)을 쓴다.
- **금지**: SF·우주·미래 도시 배경, 방패·크리스털·금속 구조물, 강한 네온·빛 번짐, 불필요한 3D, 복잡한 기하학 장식.
- CLAUDE.md의 "민트 네온 포인트, glow, 입자 효과" 문구는 위 방향으로 대체된다.
- 히어로 배경은 CSS 그라데이션으로 먼저 구현한다. 마스코트는 이번 단계에서 쓰지 않는다(나중에 별도 에셋으로 추가).

### 시그니처 선
- 얇은 민트 선을 **드문드문, 한 곳만 있어도 된다**. 전체에 깔지 않는다.
- 참고: `docs/design/signature-line.svg` (가로로 시작 → 둥근 코너로 꺾여 아래로 → 점이 찍히는 구조). 방향과 비율의 참고용이며 그대로 늘려 쓰지 않는다. 그라데이션은 가로 방향이라 세로 구간에는 맞게 바꾼다.
- 정적으로 먼저 구현한다. 모바일에서는 생략하거나 단순화한다.

### 나타나는 효과
- 스크롤하면 내용이 아래에서 올라오며 나타난다. `IntersectionObserver` + CSS transition, 한 번만 재생, 이동 20~30px / 0.5~0.8초.
- `prefers-reduced-motion`에서는 애니메이션 없이 바로 보여 준다.
- 인증 화면의 단계는 스크롤이 아니라 **사용자 행동**(이전 단계 완료)에 따라 열린다.

## 4. 와이어프레임 사용법

- `docs/design/` 아래 이미지는 이미지 AI로 만든 와이어프레임이다. **레이아웃·흐름·섹션 구조만 참고**하고, 안의 그림·문구·수치는 자리표시로 본다.
- 시안의 Riot/LoL/TFT 로고, 챔피언·캐릭터 이미지, 랭크 엠블럼은 쓰지 않는다. 자체 에셋이 들어올 빈 자리로 둔다.
- 샘플 닉네임·수치는 실제 데이터로 대체한다.
- 아직 없는 기능은 "준비 중"으로 표시하고, 있는 것처럼 보이게 하지 않는다.

## 5. 핵심 원칙: 조회 ≠ 인증

- Riot ID(닉네임#태그)만 알면 누구 계정이든 조회되므로, 조회 결과는 소유권을 증명하지 않는다.
- 조회 상태 카드: "RIOT API 조회 결과" + 조회 시각. "VERIFIED" 표시를 쓰지 않는다.
- 인증 상태 카드: 소유권 확인이 끝난 계정에만 "TIERON 인증" 배지 + 확인 시각.
- 현재 카드의 "VERIFIED BY TIERON" 문구는 조회 상태에서 바꾼다.
- 모든 카드에 "n분 전 기준"을 표시하고, 쿨다운이 지나면 재조회를 유도한다.

### 카드 데이터 (이 범위만 사용)
지역(KR), 닉네임#태그, 티어/랭크, LP, 승/패, 승률(`wins / (wins + losses)`로 계산), 기준 시각.
평균 등수, 등수 그래프, 최근 게임 전적, 시즌 전적은 구현하지 않는다. Riot API가 주는 값만 정확하게 표시하고 임의로 만들지 않는다.

## 6. 사용자 모델과 권한

| 단계 | 의미 | 가능한 것 |
|---|---|---|
| 방문자 | 로그인 안 함 | 랜딩·홈 구경, 티어 조회, 랭킹·커뮤니티 읽기 |
| 로그인 사용자 | 치지직 로그인만 | + 커뮤니티 글쓰기·댓글, 인증 시작, 카드 저장 |
| 인증 사용자 | Riot 소유권 인증 완료 | + 인증 배지, 랭킹 등록, 글쓴이 옆 인증 티어 표시, 공개 프로필 |

- 홈까지는 로그인 없이 들어올 수 있다. 로그인은 필요한 행동을 하는 순간에만 요구한다.
- 치지직 로그인은 "치지직 계정 주인"만 증명한다. 인증 배지와 랭킹은 Riot 소유권 인증이 있어야 한다.

## 7. 로그인과 DB

- 치지직 OAuth 완료 시 치지직 고유 식별값으로 `users`를 찾아 있으면 로그인, 없으면 자동 가입한다. 별도 회원가입은 없다. (치지직이 주는 식별값이 무엇인지는 개발자 문서에서 확인한다.)
- 기본키는 TIERON 자체 `id`, 치지직 식별값은 `chzzk_id`(중복 불가) 컬럼으로 둔다.
- 세션은 서버 세션 + HttpOnly·Secure·SameSite 쿠키. localStorage로 로그인 상태를 유지하던 부분은 최종 구조로 쓰지 않는다. OAuth state 검증, 서버 권한 검사, 입력값 검증, Rate Limit을 고려한다.
- DB 후보: Supabase/PostgreSQL.
  - `users`: id, chzzk_id(unique), 표시 이름, 가입일, 공개 설정 등 필요한 최소 정보
  - `riot_accounts`: PUUID, 게임 이름, 태그, 지역, user_id, 인증 상태, `verification_method`
  - `tier_verifications`: riot_account_id, 티어, 랭크, LP, **승, 패**, 기준 시각 (승률은 저장하지 않고 계산)
- 저장하는 개인정보는 최소화하고, 개인정보 처리방침에 무엇을 왜 저장하는지 적는다.

## 8. Riot 소유권 인증 (방식 미확정)

- 옛 third-party-code 방식은 2022년에 API가 제거되어 쓸 수 없다. 공식 해법은 RSO이며 별도 승인(클라이언트 신청)이 필요하다. 승인 조건과 기간은 미확인.
- 임시 후보: **프로필 아이콘 변경 확인** — 서버가 기본 아이콘 중 하나를 무작위 지정 → 사용자가 클라이언트에서 변경 → 서버가 API로 현재 아이콘 확인. 공식 인증 방식이 아니며 정책 허용 여부와 API 반영 지연을 확인해야 한다.
- 소유권 확인 단계는 **독립된 모듈로 분리**하고 `verification_method`를 저장해, 나중에 RSO로 교체할 수 있게 한다.
- 확정되기 전까지 인증 페이지는 "되는 대로" 만든다. 개발용 가짜 확인은 **개발 환경에서만** 켜지게 하고, 실제 서비스에서 확인 없이 인증이 통과되는 경로가 없도록 배포 전에 점검한다.
- 실제 확인이 붙기 전 공개용으로 올릴 때는 인증 완료 화면, 랭킹, 배지를 "준비 중"으로 둔다.

## 9. 사용자 흐름과 페이지

```
[첫 사용자]  랜딩 → 치지직 로그인 → Riot 연결·소유권 확인 → 인증 완료(카드) → 큰 "홈으로" 버튼 → 홈
[인증 안 한 사람]  랜딩의 "홈으로" → 홈 → 인증 구역·다른 기능으로 이동
```

| 페이지 | 경로(제안) | 역할 | 이번 범위 |
|---|---|---|---|
| 랜딩 | `/` | 서비스 소개, 시작·홈 버튼 | 리디자인 |
| 로그인 | `/login` | 치지직 OAuth | 완성 |
| 인증 | `/verify` | 한 페이지 안에서 단계 카드(현재 단계만 펼침, 완료는 접힘). 진행 상태는 DB 기준이라 새로고침해도 이어짐 | 소유권 확인은 임시 |
| 인증 완료 | `/verify/done` | 내 카드 + 큰 "홈으로" 버튼 | 만들기 |
| 홈(허브) | `/home` | 내 상태, 기능 입구 카드, 연결 계정 관리·설정 | 만들기 |
| 티어 조회 | `/tier` | 닉네임 검색, 조회 카드(조회 상태) | 있음, 수정 |
| 공개 프로필 | `/u/[id]` | 인증 카드 공유, OG 이미지 | 만들기 |
| 랭킹·커뮤니티 | `/community` | 탭(`?tab=ranking`)으로 게시판/랭킹. 내비 이름은 "랭킹·커뮤니티" 하나로 통일 | 게시판 최소 기능, 랭킹은 준비 중 |
| 가이드, 약관, 개인정보, 404 | | 정적 | 짧게 |
| 카드 꾸미기, 게임 선택 | | | 준비 중 입구 카드만 |

- 내비의 "티어 인증"은 인증 페이지와 헷갈리므로 조회 페이지 이름은 "티어 조회"로 한다. 게임이 TFT 하나뿐이라 "게임" 메뉴는 빼거나 준비 중으로 둔다.
- 홈에는 입구 카드를 둔다: 티어 조회·인증하기·내 프로필 공유(활성), 랭킹·카드 꾸미기(준비 중).

## 10. 랭킹 규칙

- 등록 조건: Riot 소유권 인증 완료 + 공개 설정 켬 + 랭크 데이터 있음(배치 미완료 제외).
- 정렬: 티어 → 디비전 → LP. 랭킹 대상은 TFT 일반 랭크 큐 하나로 고정한다(현재 카드가 어느 큐 데이터인지 코드에서 확인해 알려 달라).
- 갱신: 본인이 들어올 때(쿨다운 경과 시) + 수동 새로고침 버튼. 항목마다 "n시간 전 기준" 표시, 일정 기간 갱신이 없으면 흐리게 하거나 제외한다.
- 현재 시즌만 표시한다. 시즌별 기록은 나중.
- 인증 방식이 확정되기 전에는 가짜 데이터를 채우지 않고 "준비 중"으로 둔다.

## 11. 구현 순서

1. 현재 코드·CSS 파악(수정 없음) → 살릴 것/바꿀 것 정리
2. 랜딩 리디자인 (구조 먼저, 시그니처 선·나타나는 효과는 나중)
3. 치지직 로그인·세션·`users` 자동 가입
4. DB 테이블, 홈 허브, 권한 구분
5. 인증 페이지(소유권 확인 자리는 임시) → 인증 완료 화면, 카드 두 상태
6. 티어 조회 수정(조회 상태 문구·기준 시각·쿨다운), 공개 프로필
7. 커뮤니티(글쓰기는 로그인만), 랭킹은 준비 중
8. 이후: README·ERD·아키텍처 다이어그램(포트폴리오용), 배포 전 보안 점검

## 12. 아직 확인이 필요한 것

- Riot 개발자 정책에서 아이콘 확인 방식이 허용되는지, PUUID로 아이콘 조회 가능 여부와 반영 지연
- RSO 클라이언트 신청 조건·기간 (일찍 신청)
- 치지직 OAuth가 주는 고유 식별값
- Riot 관계 안내 문구(푸터)에 정책상 요구 문구가 있는지
- 현재 TFT 시즌과 카드가 사용하는 랭크 큐
- 마스코트·자체 티어 엠블럼·로고(별도 에셋, 아직 없음)
